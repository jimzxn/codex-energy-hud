# 架构与本地验证

项目采用 C# 与 .NET 10，共享数据采集集中在 `src/CodexHud.Core`。Windows x64 使用 WPF，窗口、控件、设置与诊断入口位于 `src/CodexHud`；新增 macOS Apple Silicon / Intel 使用 Avalonia 11.3.12，入口位于 `src/CodexHud.Mac`。共享层提供额度、本地任务、Token 与估算算法，平台层负责窗口、设置、自启与硬件；UI 根据采样结果刷新。

macOS 项目已在 Windows 主机完成 Release 编译，验证本次共享层变更的编译兼容性；尚未在 Mac 构建发布包、运行或验收，构建脚本和待执行验收见 [macOS 接手说明](macos.md)。此次编译保留既有 `Tmds.DBus.Protocol 0.21.2` 的 `NU1903` 依赖漏洞警告，未在本次功能中升级该依赖。本文后续 Windows 硬件、实时命名管道及本地验证命令不作为 macOS 功能或验收证据。Mac 使用独立硬件采集器，GPU/显存保持不可用；在核实桌面实时端点前，仅采用本地日志证据，不声称已确认实时审批或等待输入。

## 数据层

| 组件 | 职责 |
| --- | --- |
| `QuotaProvider` | 管理专属隐藏 app-server，通过只读账户接口采集额度与校准所需身份信息 |
| `ActivityProvider` | 读取本地任务元数据和增量日志，提供活动证据、轮次时长与任务自身 Token |
| `DesktopActivityProvider` | 只读订阅桌面实时状态，校验连续修订号，补充审批、输入等待与轮次状态 |
| `TaskNoticeTracker` | 按任务、轮次、请求去重，识别监控期间的新完成并抑制历史提醒 |
| `UsageLedgerProvider` | 独立采集本机新增响应 Token，包含归档任务及普通独立子任务，在索引层排除内部审批审查，避免 UI 筛选影响估算 |
| `WorkloadUsageProvider` | 使用独立日志游标，按首次观测时间汇总每秒整体与逐任务用量，在内存保留最近 60 个已完成 tick；不消耗估算账本的数据 |
| `SessionCostProvider` | 独立补读任务创建以来的本机逐响应记录，去重、检查完整性并累计自身及已确认后代费用，保存恢复检查点 |
| `ApiPricingCatalog` | 按版本化公开 API 价格处理模型、服务层级、缓存与长上下文，返回 USD 区间和未定价原因 |
| `QuotaTokenEstimator` | 按账户、额度池与周期对齐 Token 和额度变化，管理校准、经验范围及历史分段 |
| `HardwareProvider` | 采集整机及 Codex 进程组 CPU/GPU、内存和整机物理磁盘吞吐 |

采样结果携带时间、来源及有效性。缺失值保持未知，失败保留最后有效读数并标记过期；任务状态只表达本地记录支持的活动迹象。Token 快照不重复累加，估算也不代表套餐固定 Token 上限。完整数据口径见[使用说明](../README.md#数据含义)。

## 实时用量采集与绘制

Windows WPF 增加独立的每秒用量循环，不改变 `UsageLedgerProvider` 和 `QuotaTokenEstimator` 的既有调用。`WorkloadUsageProvider` 复用现有 Token 解析与去重逻辑，拥有独立读取游标；每秒检查变化部分，每 5 秒刷新任务索引并校验文件身份。读取继续受预算限制，轮转处理日志，避免单个大文件阻塞所有任务。

秒级样本、任务序列和整体快照携带时间、`TokenCounts` 及健康状态。快照读取不消耗数据；每条序列最多保留 60 个已完成 tick，历史不落盘。一个 tick 代表这一秒首次观测到的记录，集中上报形成波峰，不还原或平摊模型生成时间。输入包含 Cache hit，总量只加输入与输出。

启动前记录只用于基线；纳入所有有有效本地记录的普通模型、独立子任务和归档任务，排除明确的内部审批审查记录。父子任务分别计数，不向父任务重复合并。成功读完且没有新增量才报告零；未读完、半行、读取失败、文件替换和采样中断保留部分状态或缺口。单任务故障不重置其他序列，休眠恢复后不填造零点。

WPF 使用自绘折线控件，不引入图表库。654 × 134 DIP 悬浮条中约 80 × 80 DIP 的整体图与额度圆环并排；底部保留磁盘读写并增加最近完整 tick 的输入、Cache hit、输出。独立“用量”面板显示活动列表任务及最近 60 秒产生用量的子任务/归档任务，共用时间轴与纵轴尺度，采用稳定任务行以保持滚动位置。隐藏到托盘仍每秒采集，暂停绘制；恢复时直接展示最新快照。此界面接入限 Windows，共享层保持 macOS 现有调用兼容。

## 会话费用采集与定价

Windows 的“任务”与“用量”面板共用 `SessionCostSnapshot`，主任务显示自身及已确认子代理后代的累计金额，子代理行只显示自身。归档后代仍可计入；手动 fork 不建立费用继承，明确的内部审批审查不计入。归属来自日志任务 ID 与普通子代理的父任务 ID，不通过标题、目录或时间推断。父任务合计已包含后代，不能把父子行再相加。

`ShowSessionCost` 默认开启，设置勾选立即生效且跨重启保留。共享循环每 5 秒采集，关闭开关只隐藏原任务行金额，本周期账本继续读取。隐藏到托盘只暂停绘制，采集继续。费用读取与额度台账、每秒用量各有独立游标；从会话起点分批读取当前及归档日志，每轮总预算默认 4 MiB，每文件最多 512 KiB，历史补齐期间保留 Loading 状态。

只接受带响应 ID、轮次 ID 与相符任务身份的逐响应 `token_usage_record`，按任务和响应 ID 去重；对应 `turn_context` 补充模型与服务层级，响应自带元数据优先。累计 `thread_token_usage` 用于核对历史完整性，不直接套当前模型价格或重复加总。输入、缓存、输出缺失或违反子集关系时保持未定价；读取失败、预算未读完、半行、文件替换和日志缺段分别保留过期、补齐中或部分状态。

内置 `ApiPricingCatalog.Version = openai-api-2026-09-08`，附核实日期及官方来源。所有历史记录统一按该版价格重估，运行时不抓取网页，也不声称恢复历史账单。仅精确匹配受支持的模型与别名；明确的非 OpenAI provider、未知模型或未知层级未定价。缺少层级注明按 Standard 估算，`default` / `standard` 对应 Standard，`priority` / `fast` 对应 Fast；有明确但未支持的层级时不回退 Standard。

每次响应设输入为 I、缓存读取为 C、缓存写入为 W、输出为 O，公开每百万 Token 单价为 Pi、Pc、Pw、Po，则金额为 `((I - C - W) × Pi + C × Pc + W × Pw + O × Po) / 1,000,000`。输入已包含缓存读取和写入；推理 Token 已包含在输出 O 中，不另加。新模型的写入单价为普通输入的 1.25 倍；缺少 W 时，用 W = 0 与 W = I - C 给出上下界。旧模型写入按普通输入计价，不添加写入溢价。全缓存输入不会因缺少 W 产生虚假区间。

长上下文按单次响应的输入量判定，严格大于 272,000 才进入已支持的加价规则；新模型的输入及缓存乘 2、输出乘 1.5，并叠加 Fast 价格。GPT-5.4 的长请求按 Standard 长上下文价格估算，即使记录请求 Fast，也注明官方的自动回退规则。GPT-5.5 官方文档对“整个会话”的长上下文措辞尚不明确，其长请求按单请求规则给出部分估算；未公布的旧模型 Fast 长上下文组合保持未定价。规则逐模型维护，不能把这些倍率套到所有模型。

金额、计价覆盖数、未定价响应与 Token、采样时间和说明随快照返回。缓存写入缺失形成的区间仅覆盖已知响应的写入溢价，不是缺失历史或未知模型总费用的上下界；这些缺口须另标 Partial。读取故障保留此前有效金额并标记 Stale，不能确认金额时显示未知，不把缺失用量记作零。

恢复文件位于设置目录，按 Codex 数据目录摘要命名为 `session-costs-<摘要>.json`。它保存文件身份、游标、末端摘要、响应去重键、父子关系、模型、层级与 Token 等计价元数据，不保存对话正文或工具输出。检查点带版本与校验摘要，使用临时文件后原子替换；启动校验目录、文件身份与游标，无法验证时从可读日志重建，并保留缺口说明。

此功能显示公开 API Token 价格的美元等值，不是 ChatGPT/Codex 订阅扣款；未计工具调用费、区域处理加价、税费及不可见的云端或其他设备记录。费用界面只接入 Windows，共享层保持 macOS 编译兼容；Mac 功能和运行验收仍需单独完成。

## 校准状态与恢复

额度周期的接受边界与服务返回的重置时间元数据分开管理，避免单次时间戳漂移立即清空历史；回升或跨界先停止当前配对，确认新周期后归档旧段。固定边界不会随连续小幅漂移无限后移。账户、额度池及周期的记录独立，模型与 Token 结构变化只影响用法波动标记。

首次估算要求至少 3 段、每段至少 2 个百分点、合计至少 6 个百分点。恢复条件独立于首次门槛：连续两次不同时间的健康、对齐读数即可重新使用同账户同周期且未过期的合格历史，允许零新增 Token 与零额度变化。重复快照不能增加确认次数。

第 3 版状态将估算锚点与同一代 Token 台账检查点放在一个 JSON 中原子替换。额度配对使用 ReadCheckpointAsync，在台账锁内完成读取及不可变检查点捕获；普通预读不复制检查点。启动先读取估算历史，再用其中的台账检查点恢复 provider。恢复校验采样范围、目录、文件身份、读取位置、末端摘要、累计计数及去重信息；可验证的补读接续原段，无法验证的跨断档片段隔离保存，不能与后续片段拼成有效段。

首次实时额度或账户确认尚未完成时，界面按已选额度键只读显示保存的有效校准段数、累计下降及采样时间，并明确等待确认；这份摘要不提供剩余 Token 估值，不消费恢复检查点，也不绕过账户和周期校验。

第 2 版迁移保留已验证的闭合历史，无法恢复不存在的旧锚点。调整诊断区分周期复核、暂停、恢复与隔离，记录前后数值和具体原因；文件损坏、读取预算不足与持续身份不明须保持明确状态，不用零值替代。

## 任务与进程归属

当前实现提供整机和 Codex 进程组资源，不提供逐任务资源。进程组通过进程身份与父子关系识别，并排除挂件及额度采集子进程。

逐任务监控需要受支持的来源提供“任务 ID → Windows PID”，并结合进程创建时间防止 PID 重用。共享宿主、工作目录、执行会话标识或相近活动时间都不足以证明归属；独立 app-server 也不能假定拥有桌面应用已加载的任务。

未来即使取得映射，也只能统计已确认关联的本地工具进程。远程模型计算、共享桌面开销与未关联进程应分别处理。进程 I/O 字节数还可能包括网络及设备操作，不能直接等同物理磁盘读写。

## 本地验证

在仓库根目录运行以下命令。首次构建会通过 Node.js 下载并校验独立 SDK；不需要替换系统 .NET。

```powershell
./scripts/build.ps1
```

该入口构建应用并运行确定性测试，覆盖额度解析与协议、活动/时长、Token 读取、估算、实时用量与硬件算法。实时用量检查包括秒边界、60 点淘汰、启动基线、重复记录、父子任务独立计数、模型范围及读取中断；输入 100、Cache hit 80、输出 20 的整体结果须为 120。实际硬件、账户和界面检查须显式运行，命令见[使用说明](../README.md#从源码构建)。这些结果依赖执行机器，不能由单元测试替代。

费用测试覆盖 Standard / Fast 单价、缓存写入范围、长上下文边界、未知模型与层级、响应去重、历史补读、父子归属、归档、检查点恢复及读取异常。实际 UI 验收还需检查主任务和子代理的金额口径、区间与部分状态、开关即时生效、重启接续及隐藏恢复；共享层编译通过不代表 Mac 费用 UI 已验收。
构建自包含应用及运行隔离界面检查：

```powershell
./scripts/build.ps1 -Publish
./artifacts/release/CodexHud/CodexHud.exe --ui-check artifacts/validation/ui-local
```

界面检查会读取真实本地数据、生成截图和 JSON 回执并退出；它使用隔离设置。截图可能包含任务标题、额度和目录，验证产物应保留本地，分享前检查内容。

实时用量界面验收需覆盖空闲、集中波峰、多任务、长标题、大数值、缺口、切换面板和滚动位置；在各档缩放检查 654 × 134 DIP 收起尺寸、图例与底部数值，并检查屏幕边缘恢复定位。隐藏恢复时历史须连续且不补造零点。另运行至少 10 分钟，检查每秒采样是否持续积压，以及序列长度和内存是否有界；记录本次实际回执，不能复用旧版本运行证据。

实时采集的 10 分钟只读验证入口为 `--live-workload --seconds 600 --output <回执路径>`，完整命令见[使用说明](../README.md#从源码构建)。其 `passed` 只覆盖时长、完全不可用样本数和整体历史上限；检查 `samples` 中的 `readMs`、`BacklogFiles`、健康状态与内存序列，才能判断是否持续积压或增长。此入口测量独立采集器及测试进程，不能代替完整 WPF 界面运行诊断。

需要持续诊断时，先正常退出已有挂件，再运行：

```powershell
./artifacts/release/CodexHud/CodexHud.exe --exit
./artifacts/release/CodexHud/CodexHud.exe --diagnostics artifacts/validation/soak-local --soak-seconds 7200
```

确认原实例已退出后再启动诊断。诊断完成不会关闭挂件；有效采样时长应以本次 JSON 回执为准。原始资源采样和本机验收报告不随源码提交。


## 周期报告

`SessionCostProvider` 现在以同一个有预算的 JSONL 扫描提供生命周期费用投影和 `LocalUsageLedgerSnapshot`；`SetTrackedThreads` 只限制旧任务卡的投影，不裁掉报告覆盖。响应保存所有者、响应/轮次身份、记录时间与数值元数据；同一响应副本采用最早可验证时间，避免复制日志重新打时间戳后错归周期。快照集合不可变并按修订复用，费用结果逐响应缓存。旧 v1 恢复文件经原始校验后保留数值，v2 回放日志补齐新增字段。

`TaskTurnHistoryReader` 从本机 `thread_history_*.sqlite` 读取所有可用轮次，历史端点优先；日志必须具有由历史或同所有者 `token_usage_record` 证明的轮次身份，不能把无 thread_id 的继承生命周期记录算到子代理。当前任务标题从本地索引读取；缺失历史、预算不足、日志替换与不可读均保留覆盖状态。

`BillingCycleTracker` 仅依赖账户额度观测，独立保存周期与候选重置，范围按数据目录、账户、窗口隔离。120 秒内终点漂移不切周期；恢复先记首次发现时间并在 5 秒后复查，同批窗口共享事件 ID。已知卡到期信息跨缺省明细保留，卡数量下降本身不建立或确认周期。人工起点覆盖轮询估计，重复刷新不覆盖校正；临时文件原子替换保存。

`PeriodUsageCalculator` 对唯一响应做时间筛选、按 API 价格表计价，再按父子树投影。每个节点分别保留自身与组总计；模型及轮次明细是自身数据，由 GUI 递归展示。循环或孤儿关联单列且只计一次。时长为裁剪后区间并集，组内并行不重复，主组之间分别累计。缺时间戳响应不武断分配至任何周期，缺计价和缺时长各自披露。

WPF 的 `MainWindow.Billing` 在后台每 5 秒或账本/周期变化后构建报告，Dispatcher 只更新控件。报告为独立单实例窗口，HUD 收托盘不影响它；完整退出显式关闭报告与后台循环。当前周期到期、所选额度窗口消失或账户尚未确认时保留上次结果并标记周期待确认，历史报告可继续读取。
